# FIX-05 — DayView drag & drop

## Task Contract

Izvor: `agent_reports/FIX-05-task-contract.md` (puni kontekst u
`docs/dentaland-desktop-korektivni-plan.md`, sekcija 6).

Cilj: `WeekView` podržava prevlačenje termina mišem (mijenja vrijeme);
`DayView` nema drag & drop uopšte — nedosljedan mentalni model. MEDIUM
risk; jedan nezavisan reviewer (Claude), human approval obavezan prije
merge-a.

Arhitektonska odluka VEĆ donesena (ne preispitivana): DayView kolone su
**doktori**, pa drag radi SAMO unutar iste doktor-kolone (mijenja vrijeme).
Cross-doctor drag se **odbija** (drop ignorisan, termin ostaje gdje je bio)
— promjena doktora ostaje kroz "Uredi termin".

## Šta je urađeno

`desktop/views/day_view.py`, prilagođen obrazac iz `week_view.py`:

- `appointment_moved = Signal(object)` — API simetrija sa WeekView
  (nije dodatno kablovan u `main_window.py`, isto kao WeekView).
- `__init__`: `setDragDropMode(QTableWidget.DragDrop)` sa postojećim
  `# type: ignore[attr-defined]` komentarom (PySide6 stub gap) i
  `self._drag_appt_id: int | None = None`.
- `refresh()`: prazne ćelije dobijaju `ItemIsDropEnabled`, appointment
  ćelije dobijaju `ItemIsDragEnabled` (uz postojeće
  `ItemIsEnabled | ItemIsSelectable`).
- `move_appointment_to_slot(appt_id, row, col) -> bool`: dohvati termin,
  **odbije ako je `col` kolona drugog doktora**
  (`self._doctor_ids[col] != appt.doctor_id`), odbije zauzetu ciljnu
  ćeliju, izračuna `new_start = self._slot_datetime(row)` (BEZ `col` —
  DayView signature `(row, extra_minutes=0)`), `new_end` sačuvanim
  trajanjem, `store.move(...)` unutar `try/except OverlapError: return
  False`, na uspjeh `refresh()` + `appointment_moved.emit(appt)` +
  `return True`.
- `mousePressEvent` — zapamti `_drag_appt_id` iz `_appointments_by_cell()`
  na lijevi klik, pa `super()`. `_pending_click_minutes` logika NIJE
  dirana (ostaje 0; DayView nema `_half_slot_minutes_at`).
- `dropEvent` — red/kolona iz pozicije, `move_appointment_to_slot`,
  `event.accept()` na uspjeh inače `event.ignore()`.
- Importi: `QDropEvent`, `QMouseEvent` (`PySide6.QtGui`), `OverlapError`
  (`dentaland.services`).
- Ažuriran modul-docstring (više ne važi "Drag&drop ostaje
  WeekView-specific").

`store.move()` NIJE mijenjan — već mijenja samo vrijeme (nema
`doctor_id` parametar), a cross-doctor slučaj se odbija u
`move_appointment_to_slot`, ne u servisu.

## Testovi

Svi pozivaju `move_appointment_to_slot(...)` direktno (ne simuliraju
stvarne Qt drag mouse evente — isti namjerno-nefragilni obrazac kao
`test_week_view.py`):

1. `test_prevlacenje_unutar_iste_doktor_kolone_azurira_vrijeme` —
   Ljubo 09:00 → red 11:00, ista kolona → `True`; `start == 11:00`.
2. `test_prevlacenje_u_zauzetu_celiju_se_odbija` — dva Ljubina termina,
   pomak u zauzetu 11:00 ćeliju → `False`; oba zadržavaju vrijeme.
3. `test_prevlacenje_u_drugu_doktor_kolonu_se_odbija` — Ljubo 09:00 →
   Zorkina kolona → `False`; `doctor_id` i `start` nepromijenjeni.
4. `test_preklapanje_sa_terminom_van_prikaza_se_odbija` — `OverlapError`
   iz `store.move()`: termin prije radnog vremena DayView-a (07:30–08:30)
   nije u `_appointments_by_cell`, ali se vremenski preklapa sa ciljnim
   08:00 slotom → `False`; `start` nepromijenjen.
